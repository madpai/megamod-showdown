# X1: smallest original synthetic-world authoring path

**Status:** reconciled design recommendation after N1/N3/N2 landed. Current OAL [`compile_map`](https://github.com/madpai/open-asset-lab/blob/main/assetlab/package.py) starts with `SourceBSP`, then compiles its in-memory world into OALMAP. There is no original-world source path yet. Public tests already use generated synthetic BSPs; a new X1 fixture must remain original and must exercise the normal OAL validation and package writer. [Claude's X1 readiness note](../X1_READINESS.md) proposed a tiny textual world-description format; the joint decision here keeps the same compiler pipeline without committing to a new public text format.

| Path | Effort | Cleanliness / future reuse | Stable references and OAL validation | glTF fit / bypass risk |
| --- | --- | --- | --- | --- |
| **A. Test-only JSON/YAML/TOML world** | Low initial parsing effort; then schema, bounds and version decisions | Readable fixtures and easy invalid variants, but a second unpublished authoring format can become accidental public API | Good if parsed into shared normalized world and passed through shared validator; poor if special-cased by writer | Can reuse compiler stage; text schema may compete with future original/glTF sidecars |
| **B. Programmatic normalized-world fixture** | Smallest if `compile_map`'s existing writer can accept a normalized world; one extraction seam is needed | No new user-facing format; Python builders can generate reorder/duplicate/missing-target cases repeatably | Strong: fixtures use explicit placed IDs and target links, then the same validator/writer as every input. Direct binary/package writing would bypass too much and is rejected | Same normalized-world seam a future glTF importer can use; no need to design glTF import now |
| **C. Original glTF + entity sidecar** | Highest: glTF geometry, coordinate/collision mapping, sidecar grammar, importer and tests | Best creator-facing path eventually, but couples X1 to an unfinished second importer and sidecar contract | Good after both loaders converge on shared world validation | Directly advances original glTF, yet makes the first event proof wait for unrelated geometry/import work |

**Recommend B for the integration fixture.** Build a tiny Python test builder that constructs one flat ORIGINAL room, collision, starts and five generic placements with explicit IDs: Button → Relay → Door and Trigger → Teleport destination. Feed it to the **same normalized-world validation and package compile stage** used by the Source importer after that stage is extracted. The fixture may live in tests and need not be a public input format. It must not write OALMAP bytes directly or bypass reference/cycle/fanout checks. A second fixture reorders placements but keeps IDs/links, and invalid variants prove OAL diagnostics. The extraction is a small compiler seam, not a Mesh/Material/Skeleton IR redesign.

Separately, MegaMod's **runtime unit tests** may construct an equivalent tiny world directly in C. Those tests are fast checks of handle lifecycle, queue bounds, collider movement and host state. They do not replace the integration fixture. At least one end-to-end test must load the real OAL-compiled package through MegaMod's real package loader and exercise stable placed IDs, target/reference validation, generic links, moving collider and trigger definitions, the teleport target, and two-client/late-join behavior.

After X1, glTF can produce the same normalized world and a small authored-entity sidecar can be designed from observed needs. This leaves original-content support testable immediately without making Step 5 or a full editor a prerequisite.
