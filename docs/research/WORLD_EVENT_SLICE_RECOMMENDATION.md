# X1: bounded world-event vertical slice

**Status:** RESEARCH ONLY, 2026-09-26. This is a minimum contract proposal for an original synthetic `Button → Relay → Door` and `Trigger → Teleport` world. It is not a Source entity system or an implemented MegaMod feature.

## Evidence boundary

- **FACT (published API):** GMod's [Entity:Fire](https://wiki.facepunch.com/gmod/Entity%3AFire) uses the map I/O queue and carries input, optional value, delay, activator and caller; [Entity:Input](https://wiki.facepunch.com/gmod/Entity%3AInput) bypasses that queue. [GM:AcceptInput](https://wiki.facepunch.com/gmod/GM%3AAcceptInput) receives the targeted entity and input. This demonstrates why queue semantics and actor attribution need an explicit contract; it does not justify importing arbitrary input strings.
- **FACT (published API):** [Arma trigger statements](https://community.bistudio.com/wiki/setTriggerStatements) separate condition, activation and deactivation; the reported activator is available in recent Arma 3. Its broad code strings are beyond this slice.
- **FACT (published API):** [Factorio runtime events](https://lua-api.factorio.com/latest/events.html) have an event ID and tick, with event-specific fields; [event registration](https://lua-api.factorio.com/latest/classes/LuaBootstrap.html#on_event) is a script API. That suggests stable event kinds and fixed tick attribution, not a world graph implementation.
- **COMMUNITY DOCUMENTATION:** the [Creation Kit object list](https://ck.uesp.net/wiki/Cell_View_Window) exposes FormID for placed objects as distinct from EditorID and object type. MegaMod should likewise distinguish placed identity from definition identity; Bethesda's exact reference scheme is not being adopted.
- **LOCAL SOURCE OBSERVATION:** MegaMod already has [prop collision instances and host-owned breakage](../../src/engine/props.h), [imported static collision](../../src/app/match_load.c), and a [prop broken mask for joining clients](../../src/net/protocol.h). Those are useful primitives and a replication precedent. OALMAP currently has no generic placed-entity/event section.

## Minimum proposed contract

| Question | Recommendation for X1 |
| --- | --- |
| Event names or enum IDs? | Use a **small typed enum** for runtime verbs/events: `activate`, `open`, `close`, `enter`, `teleport` only as needed. OAL may accept readable names and compile them to IDs. Do not pass arbitrary strings from a client or store a universal payload table. The exact set is prototype-owned and may shrink. |
| Target identity | Links author a **stable placed ID**, unique within a world; definition IDs identify reusable kinds, not instances. OAL reports duplicates and missing targets. A world placement can keep the same ID when its file order changes. |
| Runtime references | Resolve placed IDs once at world load to generation-checked handles (pool/type, slot, generation). Revalidate generation on dispatch because targets may be destroyed or recreated. A dense slot alone must never be persisted or sent as an authored reference. |
| Queue and cycles | Host queues events for deterministic fixed-tick processing, including zero-delay links. Preserve source, target, actor and sequence/tick. Set explicit queue capacity and per-tick dispatch budget; reject or disable overflow with an attributed diagnostic. Static cycles may be warned about by OAL; dynamic loops still need the runtime budget. No delayed actions are needed for the first proof. |
| Missing targets | OAL build error for a required authored link. At runtime, reject a malformed required link at load; if a previously valid target disappears during play, drop that event with an attributed diagnostic. No silent name search or fallback to another target. |
| Door motion and collision | A door owns mutable open fraction/motion state and a moving collision instance; update its collider with its transform in the existing collision phase. Measure whether the current instance path handles a moving door before extending physics. An animated visual without a matching collider fails acceptance. |
| Authority and replication | Client sends a bounded **interact intent** identifying the target handle/placed ID and actor. Host checks reach, permissions and current state, then changes door/teleport state. Replicate durable state (`door open fraction or phase`, `relay/trigger enabled if mutable`, actor position after teleport) and reliable transitions only if presentation needs them. Clients do not execute authoritative links. |
| Late join | Send an initial snapshot of durable world state and actor positions before live deltas; sequence it against subsequent transitions. Replaying `button pressed` is insufficient to reconstruct an already open door. The existing prop mask is evidence for snapshotting an indexed mutable set, not a complete X1 protocol. |
| Offline validation | OAL checks unique placed IDs, known entity/verb kinds, type-compatible target inputs, required link existence, bounded graph size/fanout, valid trigger/collider bounds, finite transforms, and references to package-owned definitions. It reports source location/provenance. Runtime still checks counts, bounds and feature versions. |

**Proposed tiny state set:** button cooldown or pressed edge; relay enabled bit only if the test needs it; door phase/open fraction and collider transform; trigger occupancy/edge tracking; teleport destination transform and actor cooldown to prevent immediate re-entry loops. Positions, health and other existing actor state remain in their specialized systems. Start without arbitrary key/value state, script callbacks, delayed event schedulers, or a visual graph editor.

**Acceptance evidence:** an original synthetic map runs both chains on host and two clients; a late join sees the same door/collider and actor position; reordering placements does not change links; duplicate/missing target diagnostics are deterministic; a relay cycle terminates under the budget; a stale handle cannot affect a reused slot; mobile frame and network packet sizes are measured. If this slice exposes a genuine shared definition need, use its observed fields to inform X2.

**Confidence:** MEDIUM. **MegaMod applicability:** CRITICAL. **OAL applicability:** HIGH. **Status:** RESEARCH ONLY. **Implementation urgency:** NEXT. Queue, typed verbs, budgets and snapshot content are design inferences; none are claimed as measured MegaMod behavior yet.
