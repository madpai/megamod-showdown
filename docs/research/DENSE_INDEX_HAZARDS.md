# N1 follow-up: cross-peer identity carried by local positions

**Status:** reconciled with landed protocol v10 (`ac1d010`), 2026-09-26. This is a checklist for future content changes, not a request to enlarge v10. The [current compatibility contract](../CONTENT_COMPATIBILITY.md) describes the implemented guards; the [fingerprint review](V10_FINGERPRINT_ARCHITECTURE_REVIEW.md) records their limits.

| Concept | Classification after v10 | Evidence and boundary |
| --- | --- | --- |
| Imported characters | **CURRENTLY GUARDED; FUTURE RISK** | `WORLD.character` and `CONTROL.character` remain roster ordinals. v10 checks the ordered imported character array and enumerated gameplay fields before spawn. A new un-hashed gameplay field or independent character source would reopen the risk. |
| Weapons, including hidden ability shots and vehicle guns | **CURRENTLY GUARDED; FUTURE RISK** | `WORLD.weapon/carry`, `CONTROL.loadout`, `DROPS.weapon` and FX use roster positions. v10 hashes ordered imported weapons and characters; common code derives later ability/vehicle entries from these inputs and the checked world/Trial map. Final resolved `game.weapons[]` is not itself hashed. |
| Vehicle placement/type and projectile pools | **CURRENTLY GUARDED; FUTURE RISK** | `VEHICLES.index`, `GAME.hull[i]`, `PROJECTILES.pool` and detonation FX use local positions. Current Trial definitions and placements derive from the selected cache; imported weapon/ability counts are v10 checked. Future imported vehicles or independently registered pools need a new compatibility projection. |
| Breakables, props, pickup slots and choices | **PARTIALLY GUARDED; CURRENT CROSS-PEER IDENTITY RISK for binary world differences** | `GAME.prop_broken`, `WORLD.item_present` and item choices use local order. The Trial cache header CRC and OALMAP **manifest** key guard current manifest order, but the world key excludes valid binary geometry, collision group flags and spawn positions. A same-manifest binary difference can pass; see the world-key trace. |
| Teams and fixed game-mode enum | **CURRENTLY SAFE / COMPILED IDENTICALLY** | Protocol enums, not package-local arrays. Package-defined factions or modes would change this classification. |
| Built-in character/weapon definitions | **CURRENTLY SAFE / COMPILED IDENTICALLY**, conditional | Current peers run the same protocol-v10 game code and select a Trial cache; the map check uses its stored header CRC. This is compatibility detection, not a bytewise cache proof. |
| Abilities / hero powers | **CURRENTLY GUARDED; FUTURE RISK** | Abilities are embedded in hashed imported character fields and can create hidden roster shots. There is no independent ability-ID packet today. A standalone ability registry needs its own rule. |
| Materials / impact classes | **FUTURE RISK** | Current `FX.material` is a compiled enum; prop material is local world data. Material class may affect prop health. Package-defined material indices or changed binary group flags would require semantic world matching. |
| Sounds and effects | **LOCAL-ONLY / COSMETIC** for current packets; **FUTURE RISK** if package-indexed | Current packets send fixed FX kinds/material codes and clients choose sound/particles locally. No package-local sound index is sent. |
| Animation roles / skeleton slots | **UNKNOWN — NEEDS CODE REVIEW** for gameplay; otherwise **LOCAL-ONLY / COSMETIC** | Imported clips and bones stay local; `imported.c` resolves named attachment roles. Check whether an attachment changes firing origin or hitbox before declaring all animation data cosmetic. |
| Spawn classes / generic world entities | **FUTURE RISK** | Current spawn teams are in the manifest. X1 placed entities and event links need stable authored IDs and runtime handles, not a network promise based solely on package-local array order. |
| Package-local arrays generally | **FUTURE RISK** | Mesh, material, bone, clip and sound arrays are local today. Any packet/save field carrying one of their positions creates a new compatibility obligation. |

**Audit rule:** for each new packet field, identify whether it is a fixed protocol enum, a host-owned runtime slot with a mapping, or a locally reconstructed package index. The third case needs content compatibility for that index. Host authority cannot prevent a client from rendering, colliding with or naming the wrong local definition.
