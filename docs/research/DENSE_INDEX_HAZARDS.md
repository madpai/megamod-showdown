# N1 follow-up: cross-peer identity carried by local positions

**Status:** source-level architecture audit, 2026-09-26, against pre-v10 `halo-sandbox`. This complements Claude's immediate read-only inventory; it does not ask v10 to solve every future type. Classification describes **identity interpretation**, not whether a feature currently replicates complete state.

| Concept | Classification | Evidence and consequence |
| --- | --- | --- |
| Imported characters | **CURRENT CROSS-PEER IDENTITY RISK** | `WORLD.character` and `CONTROL.character` are character index + 1; [`content.c`](../../src/app/content.c) appends files from sorted `characters/`. Same position can contain a different OALASSET. |
| Weapons, including vehicle guns and hidden ability shots | **CURRENT CROSS-PEER IDENTITY RISK** | `WORLD.weapon/carry`, `CONTROL.loadout`, `DROPS.weapon`, FX use roster slots; [`match_load.c`](../../src/app/match_load.c) appends imported weapons, then [`game.c`](../../src/game/game.c) adds ability and vehicle-trigger entries. Audit the **final** roster, not just the imported file list. |
| Vehicle placement and type | **CURRENT CROSS-PEER IDENTITY RISK** | `VEHICLES.index` and `GAME.hull[i]` refer to locally loaded car position; vehicle gun slots enter the weapon roster. Trial vehicle tags are compiled in the same selected map only when map compatibility truly matches. An imported vehicle definition/placement would need explicit matching. |
| Projectile pools | **CURRENT CROSS-PEER IDENTITY RISK** | `PROJECTILES.pool` and detonation FX `weapon` can be pool indices; [`host_net.c`](../../src/app/host_net.c) iterates `game.pools` in local allocation order. Fixed host weapon/grenade pool numbers are wire constants, but ordinary pool meanings depend on the effective roster. |
| Breakables / props | **CURRENT CROSS-PEER IDENTITY RISK** | `GAME.prop_broken` is a bitset in local prop order; OAL's [`compile_map`](https://github.com/madpai/open-asset-lab/blob/main/assetlab/package.py) assigns breakable indices while building groups; [`world_fx.c`](../../src/game/world_fx.c) instantiates them in that order. Same count is insufficient. |
| Pickup item slots and choices | **CURRENT CROSS-PEER IDENTITY RISK** | `WORLD.item_present` and `item_choice[64]` are slot-indexed; [`host_net.c`](../../src/app/host_net.c) reads `s->items.slot[i].choice`. The host sends choice, but each client's local item placement/meaning still needs compatible world content. |
| Teams and fixed game mode enum | **CURRENTLY SAFE / COMPILED IDENTICALLY** | `CONTROL.team`, `WORLD` team bit and `GAME.mode` use shared protocol enums, not package-local arrays. New package-defined factions or modes would change this classification. |
| Halo built-in character/weapon definitions | **CURRENTLY SAFE / COMPILED IDENTICALLY** *conditional* | Shared compiled code and same Trial cache establish current defaults, with the existing map/cache gate. A zero/bypassed or colliding old CRC breaks that condition; v10 must fail closed. |
| Abilities / hero powers | **CURRENT CROSS-PEER IDENTITY RISK** | Current abilities are embedded in character OALASSET and can create hidden roster shots via `char_ability[]`. There is no independent ability ID packet today; matching character and final weapon/ability projection is required. A standalone ability registry is a future risk. |
| Materials / impact classes | **FUTURE RISK** | Current `FX.material` is a small compiled enum and prop material is local world data. A package-defined material array would make numeric material packets ambiguous; even now material class may affect prop default health, so it belongs to semantic world matching. Texture identity is cosmetic. |
| Sounds and effects | **LOCAL-ONLY / COSMETIC** for current packets; **FUTURE RISK** if package-indexed | Current network sends fixed FX kinds/material codes and clients choose sound/particles locally. No package-local sound index is sent. Replicating future effect or sound IDs as ordinals would create a new compatibility obligation. |
| Animation roles / skeleton slots | **UNKNOWN — NEEDS CODE REVIEW** for gameplay, otherwise **LOCAL-ONLY / COSMETIC** | Current imported model clips and bone indices stay local; `imported.c` resolves named attachment roles. They are not sent as network IDs. Confirm whether any animation role or attachment changes firing origin/hitbox before exempting all animation data from a compatibility projection. |
| Spawn classes / world entities | **FUTURE RISK** | Current spawn teams are compiled from OALMAP manifest; generic placed entities and event links are not yet in packages. X1 must use stable placed IDs for authored links and resolve runtime handles, not persist package-local array order. |
| Package-local arrays generally | **FUTURE RISK** | Mesh/material/bone/clip/sound arrays are currently local implementation details. Any later packet/save field carrying one of their positions requires either same ordered closure or a stable-ID negotiation. |

**Audit rule:** for every new packet field, write down whether it is a fixed protocol enum, host-owned ephemeral slot with a mapping, or locally reconstructed package index. Only the third needs content compatibility for that index. The host being authoritative does not prevent a client from rendering, colliding with, or naming the wrong local definition. Keep the v10 fix bounded; preserve this list as a checklist for X1/X2 and future package schemas.
